=== CHIP for AffiliateWP Changelog ===

All notable changes to this plugin are recorded here. The readme.txt shipped
with the plugin carries only the latest release's entries.

= 1.2.0 - 2026-09-16 =
* Security: the settings screen rendered the stored CHIP API key and secret into the page as input values. `type="password"` hides the display, not the value — both were in the HTML source of the settings tab, so any script, extension, or person able to read the response could take them, including the secret that signs every CHIP request. The fields are blank now, with a hint when a value is saved; an empty submission keeps the stored credential rather than clearing it.
* Security: the "webhook is not reachable" notice interpolated the whole webhook URL. Its path carries this site's per-install webhook secret, which is the only thing keeping the endpoint undiscoverable, and the notice is rendered on the settings screen. It now names the host.
* Fixed: resetting the webhook deleted every entry carrying the plugin's webhook name. That name is the same string on every install, so a merchant running two sites on one CHIP account had site A's reset remove site B's webhook — B lost its deliveries while its own settings still claimed the webhook was registered. Ownership is decided by the callback URL, which carries this site's own secret; a URL pointing at this site's route under an older secret still counts, so regenerating the secret does not orphan it.
* Fixed: an inbound delivery was resolved against the payout holding the instruction id, with no check that the delivery verified against the account that payout was sent from. Instruction ids are unique per CHIP account, not globally, so a live delivery could settle a test-mode payout and mark its referral paid.
* Fixed: the reference path read the payout id out of any `<anything>-PO-<n>`. References are unique per CHIP account, so an instruction belonging to another site on the same account — carrying that site's prefix, exactly as the plugin asks — resolved to whichever local payout held the number. The reference prefix is now required.
* Fixed: the instruction-id lookup returned the first id match and the caller then rejected it as belonging to the other environment, leaving the delivery with nowhere to go: the payout it did belong to was never looked up and stayed on processing while CHIP had already paid it. The lookup now picks the row of the account the delivery came from.
* Fixed: a payout became unresolvable after the reference prefix changed. The prefix is a setting, and its fallback is derived from the site URL, so moving the site changes it too — while the reference CHIP holds and delivers back is the one used at submission. A payout now also recognises the reference it was sent under, which cannot admit another site's instruction.
* Fixed: the single-referral path, which submits before any payout row exists, had the same prefix-only rule and stranded payouts identically.
* Fixed: adopting an instruction (one found by reference because the submission reply was lost) stored the instruction id but not the environment it came from, leaving the payout ambiguous — later checks would poll the other environment, where the id does not exist, and the webhook could not tell which account a delivery belonged to.
* Fixed: the guard that refuses to delete a bank account still in use matched on the account id alone. Account ids are per CHIP account, so a payout in the other environment holding the same number blocked the cleanup permanently: the superseded record stayed marked, the delete was refused, and it was retried on every later registration without succeeding — leaving the replaced account registered at CHIP and still offered as a payee.
* Fixed: a single-referral instruction did not record the environment it was sent in, so a later mode change pointed its checks at the other environment.
* Fixed: bank accounts were resolved against the site-wide environment rather than the payout's own, so a submission could register the recipient in the environment the money was not being sent from.
* Fixed: a payout whose environment has no credentials left now reports that, naming the environment, instead of failing without saying which set to restore.
* Fixed: deactivating the plugin left the scheduled payout checks, which carry arguments, behind.
* Under the hood: the test harness now fails when the number of checks that ran drops, rather than reporting a lower count with no failure — a test added here once sat after the summary and never ran.

= 1.1.0 - 2026-09-14 =
* Fixed: a payout that failed left its referrals unpaid but still attached to it, so the single-pay action refused them and the commission could never be paid again. Failed payouts now detach their referrals.
* Fixed: the affiliate "action required" email ended with a raw `{affiliate_payout_settings_url}` placeholder instead of a link on any site without the Stripe integration registered. The plugin now provides the tag itself and defers to an existing implementation.
* Fixed: the Malay translation never reached the site. The build only wrote the .po file, so the compiled .mo WordPress actually reads stayed at its last hand-built state; plural strings (_n) were not extracted at all. Both are fixed — 153 entries, all delivered.
* Fixed: a referral reassigned to another affiliate between batch build and submission was still paid from the original payout. Eligibility now re-checks that the referral still belongs to the payout's affiliate.
* Fixed: the webhook recovery path could create a payout row without checking the store currency, unlike the batch and single-pay paths.
* Fixed: a referral whose references CHIP had all refused looped forever. The sweep now refuses with a clear reason instead of resending a spent reference.
* Fixed: uninstall left `chip_burnt_references` behind, which suppressed a fresh reference on a later reinstall.
* Fixed: uninstall cleared scheduled hooks that no longer existed, leaving the real ones behind to fire against an uninstalled plugin.
* Fixed: the CHIP note attached to an instruction was stored unbounded (CHIP permits up to ~64 KiB) and reached the payout list and notification email. Now capped and stripped of control characters.
* Fixed: the settings screen rendered a CHIP API error message as markup. Callout content is escaped.
* Fixed: a bank account superseded by a details change was left registered at CHIP.
* Fixed: payout readiness accepted bank details CHIP would refuse.
* Fixed: a balance conversion amount that was not finite could be submitted.
* Fixed: the account summary cache was written under one key and dropped under another spelling of the same key.
* Fixed: an instruction CHIP no longer holds left the payout polling forever; it now settles with a clear reason.
* Fixed: the webhook delivery lock was taken after the payout lookup instead of before.
* Fixed: every failure code that can reach a failed payout is now classified, so the Retry button and action-required email behave consistently.
* Fixed: a recipient name is registered when the affiliate has none.
* Fixed: an amount that rounds below the smallest transferable one is refused before submission rather than by CHIP.
* Changed: the reference prefix warning now states that each site sharing a CHIP account needs its own prefix.
* Changed: terminal and settled instruction states are defined once instead of being repeated as literals.
* Removed: payout meta and review-list values that nothing read.
* Also: the coding-standards job in CI has failed since 1.0.0 because Composer blocked its installer plugin and the sniff paths were incomplete. It now installs from composer.json and runs the same command as a local checkout.

= 1.0.0 - 2026-09-01 =
* Initial release: complete CHIP Send payout integration.
* Signed API client (epoch + HMAC-SHA512 checksum) with test/live environment switching.
* Payout method ("chip") participates in AffiliateWP payout batches and single-referral payments.
* Automatic CHIP Send webhook registration (per-site secret URL, reachability-gated) with public-key capture; inbound deliveries RSA-verified; duplicate and out-of-order deliveries ignored.
* Missed-webhook healing via scheduled status checks and an hourly requery sweep.
* Idempotent payouts: deterministic unique references, existing-instruction reuse, and safe failure handling that releases referrals back to unpaid.
* Affiliate bank details (bank code + account number) on the Edit Affiliate screen with Malaysian bank codes.
* Balance card showing the allocated Send balance and what is available to convert, with a one-click budget conversion request.
* Reset webhook button to clear this site's webhook and register it again, without touching other webhooks in the CHIP account.
* Bahasa Melayu translation included (ms_MY).
* Optional recipient receipts on payouts.
